## What this is
**DocuGuard** — a full-stack AI-powered Document Intelligence & Compliance Automation system.
Users upload documents (PDF/DOCX/images); the system OCRs + extracts text, classifies the
document, validates it against compliance frameworks (HIPAA, GDPR, SOC 2, PCI-DSS), detects
violations, calls AWS Bedrock (Claude 3.5 Sonnet) for fix suggestions + summaries, calculates a
risk score, and produces downloadable audit reports. A role-based dashboard drives upload →
review → approve/reject → report.

The authoritative spec is **`PROMPT (1).md`** at the repo root. The phased build plan is in
**`DocuGuard-Development-Plan.docx`** (generated by `generate-plan.js`).

## Hard constraints (from the spec — do not violate)
- **Storage = local filesystem** under `LOCAL_STORAGE_DIR` (`./storage`), served only through
  **authenticated download endpoints**. **No S3, no cloud object storage.** Textract takes local
  file bytes directly. (An `-AsIs-S3` docx variant exists for reference only — it is NOT the design.)
- **Auth = custom JWT** (python-jose) + **bcrypt** (cost 12). No Firebase, no OpenAI, no external auth.
- **AI = AWS Bedrock only.** Every Bedrock call wrapped in try/except with a `generic_fix` fallback.
  **LIVE** as of last session via a **Bedrock API key** (bearer token in `AWS_BEARER_TOKEN_BEDROCK`).
  Model: `us.anthropic.claude-haiku-4-5-20251001-v1:0` (inference-profile ID — the `us.` prefix is
  REQUIRED; bare IDs raise ValidationException). The spec's Claude 3.5/3.7 IDs are all retired.
  Needs `boto3>=1.39` for bearer-token support (we pin `>=1.40`). `bedrock_service` creates the
  client with region only (no sigv4 keys) so botocore uses the bearer token. Textract still needs
  sigv4 keys (blank by default → fallback degrades gracefully).
- **OCR = Tesseract (local) → AWS Textract (fallback).**
- Access token in **memory only** (never localStorage); refresh token in **httpOnly cookie**.
- `extracted_text` is **AES-256 Fernet encrypted** before storing in MongoDB.
- Motor (async) for all MongoDB access — never PyMongo directly, no raw string queries.
- Celery updates the document `status` field after every pipeline step.

## Tech stack
- **Frontend:** React (Vite), Tailwind, React Router v6, Axios (JWT refresh interceptor),
  React Dropzone, @react-pdf-viewer/core + pdfjs-dist, React Toastify, Framer Motion.
- **Backend:** FastAPI, Celery + Redis, Motor, Apache Tika, pytesseract + Pillow, python-magic,
  spaCy `en_core_web_sm`, boto3, python-jose, passlib[bcrypt], reportlab, python-docx, slowapi,
  cryptography (Fernet), aiofiles.
- **Data:** MongoDB (Atlas in prod; local `mongo` container for dev), Redis (Celery broker + JWT blacklist).
- **Cloud:** AWS Textract + Bedrock (one IAM user). Local filesystem for files.

## How to run (one command)
```bash
cp backend/.env.example backend/.env   # then fill AWS keys + generate secrets
docker compose up --build
# api    -> http://localhost:8000  (Swagger at /docs)
# front  -> http://localhost:5173
```
Generate required secrets:
```bash
# JWT secret (32+ chars)
python -c "import secrets; print(secrets.token_urlsafe(48))"
# Fernet field-encryption key
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```
Seed the first admin (after stack is up):
```bash
docker compose exec api python -m app.scripts.seed_admin --email admin@docuguard.local --password ChangeMe123!
```

## Conventions
- Roles: `admin | reviewer | auditor`. Default on register = `reviewer`. RBAC via `require_role(*roles)`.
- Document status lifecycle: `pending → extracting → classifying → validating → completed | failed`.
- Approval status: `pending → approved | rejected`.
- All write actions append to `audit_logs`. Notifications in `notifications` collection.
- MongoDB ObjectIds serialized to `str` in API responses; helper in `app/utils/helpers.py`.
- API base path: `/api`. Frontend reads `VITE_API_BASE_URL`.

## Decisions / deviations (with rationale)
- **Added a `mongo` container to docker-compose** (spec lists only Atlas). Rationale: Phase 1
  objective is "run the stack locally in one command"; requiring an Atlas signup breaks that.
  `MONGODB_URI` still points at Atlas in production by editing `.env`.
- Kept everything else exactly to spec.

## Gotchas
- `passlib[bcrypt]==1.7.4` breaks with `bcrypt>=4.1` → pinned `bcrypt==4.0.1`.
- `python-magic` needs `libmagic1` (installed in the backend Dockerfile) — won't import on bare Windows; run via Docker.
- Tika needs Java (`default-jdk` in Dockerfile); spaCy model downloaded at image build time.
  Tika also fetches its server jar from Maven on first use (one-time network, not AWS).
- `EmailStr`/email-validator **rejects reserved domains** like `*.local` → use real-looking
  domains (e.g. `@example.com`) for API registration and tests. (`seed_admin` inserts directly
  into Mongo, bypassing this validation, so an `admin@docuguard.local` seed is fine.)
- QA harnesses: `backend/tests/test_offline.py` (in-container, no AWS) and `scripts/qa_http.py`
  (host, stdlib-only). Run the offline one first — it generates the DOCX fixture the HTTP one uploads.
